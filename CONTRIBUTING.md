# Contributing to Emulator UI

Thanks for your interest! Bug reports, ideas and pull requests are all welcome.

- **Bugs and feature ideas:** open an [issue](https://github.com/D33ptar00p/emulator-ui/issues/new/choose) using one
  of the templates.
- **Security problems:** never open a public issue. Follow [SECURITY.md](SECURITY.md).
- **Small fixes** (typos, docs, obvious bugs): send a pull request directly.
- **Bigger changes** (new pages, new dependencies, architecture changes): open an issue first, so we can agree on
  the approach before you spend time on it.

## Development setup

You need Docker, [uv](https://docs.astral.sh/uv/), Node 22 and a running AWS Emulator (see
[Emulator requirements](README.md#emulator-requirements)).

```bash
git clone https://github.com/<you>/emulator-ui.git && cd emulator-ui
uv sync                      # Python env with dev tools
source scripts/emulator-env.sh
make dev                     # API on :8081 (reload) + UI on http://127.0.0.1:5173
```

To try the real container instead: `make up` (http://127.0.0.1:8080).

## Before you open a pull request

```bash
make lint       # ruff (lint + format check) and shellcheck
make test       # backend tests; the live API tests need a running emulator
make ui-test    # frontend typecheck + vitest
```

- **Add or update tests** for any behaviour you change. Backend tests are in `tests/`; frontend tests sit next to the
  code as `ui/src/**/*.test.ts`.
- **Match the existing style:**
  - Python with type hints, formatted by ruff;
  - React function components in TypeScript (strict);
  - no new runtime dependencies without discussing them first.
- **Keep the console local-only and safe.** Don't weaken the localhost, CSRF or relay guards described in
  [SECURITY.md](SECURITY.md).
- **Artwork must be original.** Don't add third-party logos or icons. Service icons are generated by
  `scripts/build_icons.py`; regenerate them with `make catalog`.
- **Keep pull requests focused,** one change per PR, with a description of what changed, why, and how you tested it.
  Screenshots help for UI changes.

## Project layout

| Path | What's there |
|---|---|
| `src/emulator_ui/` | FastAPI backend: `routers/` (API), `aws.py` (boto3 sessions), `regions.py`, `relay.py`, `inventory.py` |
| `ui/src/` | React frontend: `pages/` (one per hand-built service), `OperationRunner.tsx` (generic runner) |
| `scripts/` | catalog and icon generators, inventory baseline, container scripts |
| `tests/` | backend tests |

To add a hand-built page for a service:
1. add a router in `src/emulator_ui/routers/` and register it in `app.py`;
2. add a page in `ui/src/pages/` and register it in `ui/src/App.tsx` and `ui/src/services.ts`;
3. add tests.

Every other service already works through the generic explorer (`#/svc/<id>`).

## How pull requests are merged

`main` is protected: changes land through pull requests, which the maintainer reviews and merges. Expect a reply
within a few days, since this is a spare-time project.
